21 // How long the whole exchange gets: one connect, one request line, one answer. The control plane
22 // answers one short request per connection and closes, it is reached over the loopback interface,
23 // and it gives a peer that has not spoken five seconds before it drops it -- so this is longer than
24 // everything the far end does and short enough that a run pointed at nothing does not hang.
25 //
26 // It is one deadline for the exchange and not one per read: a peer that drips a byte at a time
27 // would never run out of reads, and a run any peer can keep waiting for as long as it likes is a
28 // run whose caller has no bound to lean on.
